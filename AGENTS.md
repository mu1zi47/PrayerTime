# Project workflow

After each completed code change, build the Android release APK and install it
on the user's connected phone. The user explicitly requested this workflow.
If the phone is disconnected or installation fails, report that clearly.

# Единая дизайн-система

Во всех изменениях интерфейса использовать общую дизайн-систему из
`lib/theme/app_design_system.dart` и переиспользуемые компоненты `lib/widgets/`.
Цвета, отступы, типографику, размеры, радиусы и анимации брать из общих токенов.
Не задавать отдельное оформление экземплярам одного типа компонента.
Кнопки действий оформлять через общий `PillButton`, поверхности — через
`GlassPanel`; радиусы кнопок и панелей должны совпадать. Если нужен новый
вариант, определять его централизованно, а не локально на экране.

Строки намазов на главном экране и в календаре строить через общий
`PrayerRowLayout`: единая высота, симметричные слоты и выравнивание времени
внутри варианта. Вариант `plain` без рамки — без бокового внутреннего
отступа; `contained` внутри рамки/панели — с общим отступом из токенов.
Восход и другие строки без отметки сохраняют пустой слот той же ширины и высоты.
При правках размеров проверять все состояния, включая строки без кнопки
и активную строку; не менять локальные отступы строк по отдельности.

Цвета иконки приложения также брать из общей палитры. SVG-исходники в
`assets/icon/` синхронизируются через `tool/sync_design_tokens.py`;
для обновления PNG и иконок всех платформ запускать `python3 tool/generate_app_icons.py`.
