# Задание ИИ-разработчику: реализация главного экрана Flutter (v0.5)

## Цель

Переделай **только главный экран существующего Flutter-приложения** в соответствии с согласованной композицией. Это **рефакторинг интерфейса, а не переписывание приложения с нуля**. Сначала изучи текущий проект, маршруты, модели расписания, механизм расчёта времени намазов, хранение отметок, локализацию и настройки. Сохрани работающую бизнес-логику и существующие экраны.

## Источники истины и приоритеты

1. **Визуальная композиция:** приложенный референс-скриншот `home_reference.png` (скриншот, выбранный пользователем). Он определяет общий характер, расположение элементов, форму акцентного таймера и трёх кнопок.
2. **Точные CSS-токены и пример структуры:** `design_reference/index.html` — HTML-прототип v0.5. Изучить CSS и разметку, но **не копировать ошибки демонстрационной логики**.
3. **Правила поведения:** настоящий документ и уже существующая логика приложения. Если предыдущие README/UX_SPEC противоречат этому заданию в отношении главного экрана, приоритет у этого файла.
4. Если чего-то нет в исходниках или документации, не придумывать новую бизнес-логику: спросить.

Важно: HTML — **визуальный прототип**, а не рабочий источник данных. В нём статичные времена, таймер, статусы, заглушки переходов и ошибочная привязка подсветки строки к статусу `late`. В Flutter всё это нужно заменить реальной логикой.

## Утверждённая структура экрана (сверху вниз)

1. Системный status bar ОС — **не рисовать вручную**.
2. Верхняя строка: слева иконка геолокации + выбранный город + стрелка вниз; справа иконка настроек. **Нет даты, дня недели, колокольчика и нижней навигации**.
3. Блок следующего намаза **без большого внешнего контейнера**: слева надпись «Следующий намаз» и крупное название (например, «Аср»), справа отдельная выразительная капсула с подписью «через» и **крупным обратным отсчётом** `HH:MM:SS`. При переходе через полночь/после Иши корректно указывать «Завтра» возле контекста следующего намаза. Не подменять обратный отсчёт временем наступления.
4. «Быстрый доступ» + ссылка «Все» справа. Под заголовком **три одинаковые кнопки в ряд**: иконка сверху, подпись снизу. По умолчанию: «Карта мечетей», «Календарь намазов», «Имена Аллаха». Пользователь может заменить каждую из трёх кнопок инструментом из доступного каталога.
5. Заголовок расписания **«Сегодня»** + ссылка «На месяц» справа.
6. Лёгкий список из шести строк в порядке: **Фаджр, Восход, Зухр, Аср, Магриб, Иша**. Слева иконка статуса/восхода, по центру только название, справа **только время наступления `HH:MM`** и, если нужно, шеврон. **Никаких текстов «Прочитан вовремя», «Прочитан с опозданием» внутри строки. Никакого обратного отсчёта в расписании.**

## Статусы и активная строка — принципиально важно

- `onTime`: зелёная круглая иконка с галочкой.
- `late`: золотая иконка часов.
- `unmarked`: нейтральный пустой круг.
- `sunrise`: отдельная иконка восхода; **не намаз**, не отмечается, модалка отметки не открывается.
- Статус намаза и **текущий временной интервал** — разные сущности.
- Выразительная акцентная полоса с тонкой золотистой границей и скруглением выделяет **текущий намаз по времени**, а **не** тот, который прочитан с опозданием. Если текущий интервал не определён, не подсвечивать случайную строку. Время справа всегда `HH:MM`.
- Акцентная строка должна выглядеть как в референсе: цельная мягкая горизонтальная плашка на фоне лёгкого списка, а не тяжёлая отдельная карточка. Отступы и разделители не должны «зажимать» содержимое.
- Не делай вывод, что отсутствие отметки означает пропущенную молитву.

## Взаимодействия

- Город → существующий выбор города; после смены обновить расписание и обратный отсчёт.
- Настройки → существующий экран настроек.
- Нажатие на любой из пяти намазов → существующая нижняя модалка отметки: «Прочитал вовремя», «Прочитал с опозданием» и «Убрать отметку» (только если отметка уже есть). После выбора сохранить отметку через существующий механизм, закрыть модалку, сразу обновить иконку. Не ломать календарь намазов и синхронизацию отметок.
- Восход → информационная строка без отметки.
- «На месяц» → существующее месячное расписание.
- Три быстрых действия → существующие экраны соответствующих функций.
- «Все» → экран каталога инструментов без нижней навигации. Каталог открывает существующие функции и предоставляет **явное** действие «Настроить быстрый доступ».
- Настройка: три слота, выбор из доступных реализованных функций; дубликаты не допускаются (при выборе уже занятого инструмента можно менять слоты местами); изменения сохраняются локально и восстанавливаются после перезапуска.
- **Киблу не добавлять как работающую кнопку, пока функция не реализована**. Не добавлять друзей, стрики, уведомления или иные новые функции.
- Кнопка «Назад» возвращает пользователя в исходный экран; не создавать лишних промежуточных маршрутов.

## Визуальные токены из HTML v0.5

Применить в Flutter как константы темы, без случайных оттенков:

| Токен | Значение |
|---|---|
| Фон | `#0B192C` |
| Поверхность | `#15263C` |
| Золотой акцент | `#E9B950` |
| Основной текст | `#F4F2EF` |
| Вторичный текст | `#9CA8B7` |
| Разделитель | `#24364A` |
| Зелёный статус | `#58BD91` |
| Контейнер обратного отсчёта | радиус ~28 px, тёмная градиентная поверхность, тонкая золотистая граница |
| Кнопки быстрого доступа | радиус ~22 px, высота ~108 dp в эталоне, тонкая рамка |
| Строки расписания | минимум ~72 dp, тонкий нижний разделитель |
| Активная строка | радиус ~24 px, приглушённая золотисто-тёмная поверхность |
| Иконки статусов | область ~44×44 dp |

**Примечание о единицах:** CSS px в референсе и Flutter logical dp близки по смыслу для проектирования, но **не переносить размеры механически**: учитывать SafeArea, реальные ширины устройств, textScaleFactor, перенос подписей и системные панели. Эталон HTML ограничен шириной 440 px, имеет горизонтальный padding 24 px, но в Flutter ширина должна быть адаптивной.

Типографика HTML: системный sans-serif (Inter/системный fallback); заголовок следующего намаза ~57 px, отсчёт ~31 px, заголовки секций ~20 px, строки ~18 px. Использовать согласованный шрифт проекта, если он уже задан; не подключать новые шрифты без необходимости. Иконки должны быть стилистически согласованными и доступны в проекте (Material или существующий набор), а не emoji/символы-заглушки.

## Техническая реализация

- Сохраняй текущую архитектуру проекта (state management, router, repositories, локализация). Не внедряй новые библиотеки, если уже есть эквиваленты.
- Используй `SafeArea` и один вертикальный scroll-контейнер. Никаких искусственных статус-баров и фиксированных нижних панелей.
- Таймер рассчитывать из `nextPrayerDateTime - DateTime.now()` с обновлением не реже 1 раза в секунду, отменой подписок/таймеров в `dispose`, пересчётом после возвращения из фона, смены дня, города, метода расчёта и часового пояса. Не использовать захардкоженное `06:55:00`.
- Правильно определять следующий намаз: только пять обязательных намазов; **восход не может стать следующим намазом**.
- Строка «текущий намаз» определяется реальными интервалами времени приложения, **независимо от отметки**. После Иши и до Фаджра следующего дня — использовать согласованное правило текущего состояния; если правило не реализовано, уточнить до кодирования подсветки.
- Сохранить доступность: кликабельные области примерно 44–48 dp, семантические подписи для иконок и статусов, корректный контраст, масштабирование шрифтов.
- Не копировать HTML-обработчики, `localStorage` или статичные данные напрямую во Flutter.
- Данные расписания, статусов и города должны идти из действующих моделей/сервисов проекта.

## Что не нужно делать

- Не переписывать другие экраны ради внешнего вида главной.
- Не менять алгоритмы расчёта намазов, методы/мазхабы, уведомления, отметки, локализацию и хранилище без необходимости.
- Не возвращать дату, колокольчик, нижнюю навигацию, кнопку «Отметить все» или большие декоративные блоки.
- Не добавлять арабские подписи и описания статусов в строки главной, если их нет в выбранном визуальном эталоне.
- Не привязывать золотую активную строку к опозданию (это ошибка демонстрационного HTML).
- Не придумывать новые разделы и функции.

## Порядок работы для ИИ-разработчика

**Этап 1 — аудит (без изменений кода).** Перечисли обнаруженные файлы главной, маршрутов, расчёта времени, отметок, настроек и существующих экранов. Кратко объясни, что будет переиспользовано. Укажи недостающие зависимости/неясности.

**Этап 2 — план.** Дай список конкретных файлов для изменения/создания, опиши структуру виджетов (`HomeScreen`, `NextPrayerHeader`, `CountdownPill`, `QuickActions`, `PrayerSchedule`, `PrayerRow`, `PrayerMarkSheet` — названия примерные) и источники данных. Сначала покажи план пользователю. **Дождись подтверждения, прежде чем менять код.**

**Этап 3 — реализация.** После подтверждения реализуй главную в соответствии с референсом. Переиспользуй существующие экраны и модели. Старайся не затрагивать несвязанный код.

**Этап 4 — проверка.** Запусти форматирование, статический анализ, доступные тесты и сборку, если окружение позволяет. Сделай скриншот реального Flutter-экрана и сравни его с референсом по композиции, размерам, иконкам и плотности. Не заявляй, что дизайн совпадает, без визуальной проверки.

## Критерии приёмки

- [ ] Визуальная композиция повторяет выбранный скриншот и HTML v0.5, а не произвольную «тему намазов».
- [ ] Нет большой даты, колокольчика и нижней навигации.
- [ ] Большой обратный отсчёт находится **только в отдельной капсуле сверху**.
- [ ] На главной три настраиваемые кнопки; их выбор сохраняется.
- [ ] В расписании шесть строк; справа у каждой только время `HH:MM`.
- [ ] Статусы отображаются иконками без текстовых описаний.
- [ ] Подсветка строки зависит от текущего времени, не от `late`.
- [ ] Восход нельзя отметить.
- [ ] Модалка отметки работает с существующим хранилищем.
- [ ] Все существующие переходы работают; другие функции не сломаны.
- [ ] Интерфейс корректен на узком Android-экране и при увеличенном шрифте.
- [ ] Разработчик показал список изменённых файлов и скриншот результата.
